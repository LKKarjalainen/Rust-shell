Stages 01–08

Core

Gets you a working REPL and the four builtins everything else is measured against. The decision here: where command dispatch lives. An enum Builtin plus an exhaustive match means adding a builtin later is a compile error until you handle it, instead of a silent no-op.

  1. 01

    Print a prompt introductionVery easy

    Print $ with no trailing newline, then flush. Without the flush the prompt sits in the buffer and the harness sees nothing.

    print!("$ ");
io::stdout().flush().unwrap();
  2. 02

    Handle invalid commands cz2Easy

    Read one line and report an unknown command. Real bash writes this to stderr; the harness reads both, so either works for now.

    $ nonexistent
nonexistent: command not found
  3. 03

    Implement a REPL ff0Easy

    Wrap the prompt and read in a loop. Watch for EOF: read_line returning Ok(0) means stdin closed and you must break, or you spin forever burning CPU.

  4. 04

    Implement exit pn5Easy

    exit 0 terminates with that status. A method cannot break its caller's loop, so this is what forces a return type — an enum with a payload variant carries the code out.

    Loop::Exit(args.first().and_then(|a| a.parse().ok()).unwrap_or(0))
  5. 05

    Implement echo iz3Easy

    Print the arguments separated by a single space. args.join(" ") puts separators between elements, which avoids the trailing space a push-loop leaves behind.

  6. 06

    Implement type ez5Easy

    Report whether a name is a builtin. Ask the enum — Builtin::from_name(x).is_some() — rather than keeping a parallel list of names that can drift out of sync.

    $ type echo
echo is a shell builtin
$ type nope
nope: not found
  7. 07

    Locate executable files mg5Medium

    Split $PATH on :, join each entry with the command name, and take the first hit that exists and has an executable bit set. That needs std::os::unix::fs::MetadataExt and a mode() & 0o111 != 0 test.

    $ type ls
ls is /usr/bin/ls
  8. 08

    Run a program ip1Medium

    Execute the resolved program with its arguments. Prefer spawn() + wait() over output(): output() buffers both streams to completion, which breaks interactive programs and makes it easy to drop stderr. spawn() inherits your stdio so the child writes straight to the terminal, and you keep the ExitStatus for $? later.

Stages 09–12

Navigation

Four small stages that quietly introduce shell state. The decision here: process globals or a Shell struct. env::set_current_dir mutates the whole process, which you cannot unit-test and cannot snapshot for a subshell. Holding cwd in a struct threaded by &mut costs nothing now and saves a rewrite at stage 55.

  1. 09

    The pwd builtin ei0Easy

    Print the absolute working directory. env::current_dir() returns a PathBuf; .display() is the idiomatic way to print it.

  2. 10

    The cd builtin: absolute paths ra6Medium

    Change directory, and print the exact error text when the target is missing.

    $ cd /nope
cd: /nope: No such file or directory
  3. 11

    The cd builtin: relative paths gq9Medium

    ./dir, ../, and . must all work. set_current_dir resolves these against the process cwd already, so this is often free once stage 10 passes.

  4. 12

    The cd builtin: home directory gp4Medium

    Bare cd and cd ~ both go to $HOME. Read the variable with env::var("HOME") — the harness sets it, and depending on it explicitly is more predictable than a helper. Note this is only ~ alone; ~/dir and ~user are not part of this stage.

you are here
Stages 13–18

Quoting

The wall. Splitting on a space cannot express any of these six stages, because quoting is a state machine, not a delimiter rule. Write fn lex(&str) -> Vec<String> that walks the input character by character tracking one of four states — plain, single-quoted, double-quoted, escaped — and pushes into a current-word buffer. It returns owned Strings, not &str, because a"b"c becomes one word assembled from pieces. Every stage below is then one rule inside that machine, and each is directly unit-testable.

  1. 13

    Single quotes ni6Medium

    Everything between ' and the next ' is literal, and the quotes themselves are removed. Interior whitespace no longer splits words.

    $ echo 'hello   world'
hello   world
  2. 14

    Double quotes tg6Medium

    Same word-joining as single quotes, but a different escape rule inside — handled in stage 17.

    $ echo "quz  hello"  "bar"
quz  hello bar
  3. 15

    Backslash outside quotes yt5Medium

    A backslash makes the next character literal, including a space, and then disappears.

    $ echo world\ \ \ script
world   script
  4. 16

    Backslash within single quotes le5Medium

    Inside single quotes a backslash is an ordinary character. There are no escapes at all in single quotes — that is the whole rule.

    $ echo 'shell\nscript'
shell\nscript
  5. 17

    Backslash within double quotes gu3Medium

    The awkward one. Inside double quotes a backslash escapes only $, `, ", \ and newline. Before anything else it stays a literal backslash and the character follows normally.

    $ echo "hello\"insidequotes"
hello"insidequotes
$ echo "before\   after"
before\   after
  6. 18

    Executing a quoted executable qj0Medium

    Runs a program whose filename contains spaces. Nothing new in the lexer — this is the stage that catches you if you re-split the words anywhere downstream of it. Resolve and execute from the token list, never from the raw line.

    $ 'exe with space' file.md
Stages 19–22

Redirection

First stage where a flat token list stops being enough: you need to separate the operator from the words around it. The decision here: builtins must obey redirection too, so they can no longer call println!. Give each builtin a &mut dyn Write to write into — the loop passes io::stdout() normally and a File when redirected. That one signature change also makes builtins testable against a Vec<u8>.

  1. 19

    Redirect stdout jv1Medium

    Both > and the explicit 1> truncate-or-create the target file. Use File::create, and for external commands hand the file to Stdio::from(file).

    $ echo hello 1> out.txt
  2. 20

    Redirect stderr vz4Medium

    2> sends the error stream instead. The file descriptor number is part of the token, so your parser has to read it rather than matching on > alone.

  3. 21

    Append stdout el9Medium

    >> and 1>> append instead of truncating: OpenOptions::new().append(true).create(true).

  4. 22

    Append stderr un3Medium

    2>>. If stages 19–21 pushed you into a small Redirect { fd, target, append } struct, this one is already done.

Stages 23–28

Command completion

A hard pivot: read_line can no longer be your input path, because you need each keystroke as it arrives. That means raw terminal mode — crossterm is the usual choice, and CodeCrafters allows crates. The decision here: use a readline library or write your own line editor. Writing it yourself is the point of the challenge and stages 58–63 need the same buffer for history, so build a small LineEditor that owns the buffer, the cursor, and the terminal state.

  1. 23

    Builtin completion qp2Medium

    TAB on a prefix of a builtin name completes it and appends a space. ech + TAB becomes echo .

  2. 24

    Completion with arguments gm9Medium

    After completing, typing continues normally and the finished line still executes. Confirms your editor's buffer and the terminal's display never drift apart.

  3. 25

    Missing completions qm8Easy

    No match rings the terminal bell — print \a — and leaves the buffer untouched.

  4. 26

    Executable completion gy5Medium

    Completion source widens from the builtin enum to every executable across $PATH. Scan the directories and collect names; dedupe, because the same name can appear in several entries.

  5. 27

    Multiple completions wh6Hard

    One TAB with several candidates rings the bell; a second TAB prints them on one line, sorted and space-separated, then redraws the prompt with the buffer intact. You now need to track whether the previous keypress was also a TAB.

  6. 28

    Partial completions wt6Hard

    When candidates share a longer prefix than what was typed, complete to that longest common prefix and add no trailing space. Write the LCP as its own function — stage 44 needs it again.

Stages 29–35

Filename completion

The same machinery aimed at the filesystem instead of $PATH. The decision here: completion source becomes context-dependent — the first word completes commands, later words complete paths. If stages 23–28 hardcoded "look in PATH", this is where you refactor to a function that takes the word and its position and returns candidates.

  1. 29

    File completion zv2Medium

    Complete a filename in the current directory from its prefix, via fs::read_dir.

  2. 30

    Nested file completion ue6Medium

    src/ma + TAB completes inside src/. Split the word at the last /: everything before is the directory to read, everything after is the prefix to match.

  3. 31

    Directory completion lc6Easy

    A directory completes with a trailing / and no space, so you can keep descending. Check metadata.is_dir() per candidate.

  4. 32

    Missing completions vs5Easy

    Bell on no match, same as stage 25 — but also handle the directory simply not existing, which is an Err from read_dir rather than an empty list.

  5. 33

    Multiple matches no5Hard

    Double-TAB lists matching filenames. List the bare names, not the full paths you read them from.

  6. 34

    Partial completions jp8Hard

    Longest common prefix again, on filenames. Reuse the function from stage 28 unchanged — if you cannot, it was written against the wrong type.

  7. 35

    Multi-argument completions bf8Easy

    Completion works on the third, fourth, nth word too — not just the second. Falls out for free if you located the current word by cursor position rather than by index.

Stages 36–45

Programmable completion

Users register their own completion commands with complete, and your shell shells out to them. The decision here: this is the first genuinely stateful builtin — it owns a registry that outlives any one invocation. An enum Builtin match arm cannot hold a HashMap, so either put the registry on your Shell struct and pass &mut Shell into run, or switch to trait objects that own their state. The Shell struct is the smaller change.

  1. 36

    Register complete builtin ne7Easy

    Add complete as a builtin that accepts a registration and stores it.

  2. 37

    Printing missing specifications oi7Easy

    complete -p unknown reports that no specification exists for that name.

  3. 38

    Displaying registered specifications wl6Medium

    complete -p with no name prints every registration. Sort the output — HashMap iteration order is deliberately unstable in Rust and will fail the test intermittently. Use BTreeMap or sort the keys.

  4. 39

    Single completion pm5Medium

    TAB on a registered command runs its completer program and uses the output — one candidate per line — as the candidate list.

  5. 40

    Handling no completions qf1Easy

    A completer that prints nothing means no candidates: bell, buffer unchanged.

  6. 41

    Passing command-line arguments zi0Easy

    The completer receives the command name, the word being completed, and the preceding word as its three positional arguments.

  7. 42

    Passing environment variables nr7Easy

    Set COMP_LINE (the whole line) and COMP_POINT (cursor offset) in the child's environment via Command::env.

  8. 43

    Multiple completer candidates ep2Easy

    Several output lines follow the double-TAB listing rules from stage 27.

  9. 44

    Longest common prefix xz3Medium

    LCP applied to completer output. Third use of the same function.

  10. 45

    Unregister a completion tz2Easy

    complete -r name removes one registration and completion falls back to the default behavior.

Stages 46–54

Background jobs

Your shell stops waiting for its children. The decision here: a job table on the Shell struct — job number, PID, command text, status — and a non-blocking reap. Child::try_wait() in std covers this without pulling in nix: it returns Ok(None) for a still-running child instead of blocking. Real job control (Ctrl-Z, fg, process groups) needs raw waitpid and signals, but these stages do not go that far.

  1. 46

    The jobs builtin af3Easy

    Add jobs; with nothing running it prints nothing and exits cleanly.

  2. 47

    Starting background jobs at7Medium

    A trailing & spawns without waiting and prints the job number and PID.

    $ sleep 5 &
[1] 12345
  3. 48

    Printing background job output si2Medium

    A background child keeps the terminal's stdout, so its output appears whenever it appears — interleaved with your prompt. Do not capture it.

  4. 49

    List a single job jd6Medium

    jobs shows the running job with its number, status, and the command as typed — so store the original text at spawn time.

    [1]+  Running                 sleep 5 &
  5. 50

    List multiple jobs dk5Medium

    Several jobs list in order, with + marking the current job and - the previous one. Those two markers are positional, not stored flags.

  6. 51

    Reap one job ma9Medium

    A finished job reports Done and leaves the table.

  7. 52

    Reap multiple jobs rq2Medium

    Several finish together and all are reported. Collect the finished ones before mutating the table — removing while iterating will not borrow-check, which is the borrow checker catching a real bug.

  8. 53

    Reap before the next prompt bv8Medium

    Timing stage: the Done lines must print immediately before the prompt is drawn, not after the next command. One reap call at the top of the loop.

  9. 54

    Recycle job numbers fy4Easy

    New jobs take the lowest free number, not a monotonic counter. Scan the table for the first gap.

Stages 55–57

Pipelines

Three stages, all rated hard, and the reason a flat command representation finally breaks. The decision here: an AST. enum Node { Command { words, redirects }, Pipeline(Vec<Node>) }, with the parser producing it and execution walking it. Chain externals by handing each child's ChildStdout to the next as Stdio::from. Spawn every stage before waiting on any of them, or a full pipe buffer deadlocks you.

  1. 55

    Dual-command pipeline br6Hard

    ls | wc -l. Spawn both with Stdio::piped(), wire the first child's stdout into the second's stdin, then wait on the last.

  2. 56

    Pipelines with built-ins ny9Hard

    A builtin inside a pipeline — echo hi | wc -c. It has no process to pipe from, so it must write into the pipe. This is where the &mut dyn Write signature from stage 19 pays off: hand it the child's stdin instead of a file.

  3. 57

    Multi-command pipelines xk3Hard

    Arbitrary length. If stage 55 was written as a fold over a vector of stages rather than a special case for two, this passes immediately.

Stages 58–63

History

Reuses the line editor from stage 23 — arrow keys are escape sequences arriving on the same raw-mode input path. The decision here: history is a Vec<String> on the Shell struct plus a browse cursor that is not the same thing as its length. Keep the in-progress line saved separately when the user arrows away from it and back.

  1. 58

    The history builtin bq4Easy

    Add history. Decide now whether the history command itself gets recorded — bash records it.

  2. 59

    Listing history yf5Medium

    Numbered from 1, right-aligned in a fixed-width column, command text after. Format with {:>5}.

        1  echo hello
    2  pwd
  3. 60

    Limiting history entries ag6Medium

    history 3 shows only the last three — but keeps their original numbers, not 1–3. Slice the tail and offset the index.

  4. 61

    Up-arrow navigation rh7Medium

    Up walks backward through history, replacing the visible line. Redrawing means clearing to end of line — the old text does not erase itself.

  5. 62

    Down-arrow navigation vq0Medium

    Down walks forward, and past the newest entry restores the draft the user was typing. That draft is why the cursor and the vector length are separate pieces of state.

  6. 63

    Executing commands from history dm2Medium

    A recalled line runs normally, and is appended as a new entry rather than moving the old one.

Stages 64–69

History persistence

History survives restarts. The decision here: track how much of the in-memory history has already been written, so append can write only the new tail. That is one usize watermark on the struct, and forgetting it is what makes stage 66 duplicate entries.

  1. 64

    Read history from file za2Medium

    history -r path loads lines from a file onto the end of the current history.

  2. 65

    Write history to file in3Medium

    history -w path writes everything, truncating the file first.

  3. 66

    Append history to file sx3Hard

    history -a path appends only entries added since the last write or append. This is the watermark stage.

  4. 67

    Read history on startup zp4Easy

    If $HISTFILE is set, load it before the first prompt. A missing file is normal, not an error.

  5. 68

    Write history on exit kz7Easy

    Flush to $HISTFILE when exit runs. Note process::exit skips destructors, so this has to happen explicitly before the call — not in a Drop impl.

  6. 69

    Append history on exit jv2Medium

    Append rather than overwrite on exit, so two shells running at once do not clobber each other.

Stages 70–76

Parameter expansion

The last group closes the loop back to the lexer. The decision here: expansion is a separate pass, run after tokenizing and before execution — because whether $X expands depends on the quoting context the lexer already resolved. If your lexer throws away which quotes a character came from, you will be adding that information back here. Tagging each token with its quote context at stage 13 avoids the rework.

  1. 70

    The declare builtin ji0Easy

    Add declare. Another stateful builtin, reading and writing the variable map on your Shell.

  2. 71

    Printing missing variables oa2Easy

    declare -p X for an unset name reports that it was not found and returns non-zero.

  3. 72

    Storing shell variables kv5Medium

    declare X=value stores it and declare -p X reads it back. Split on the first = only — values legitimately contain more.

  4. 73

    Validating variable names db8Easy

    A name must start with a letter or underscore and continue with letters, digits, or underscores. Anything else is an error. Doable with chars(); no regex crate needed.

  5. 74

    Expanding variables ge9Hard

    $X expands in plain and double-quoted words, never in single-quoted ones. The name ends at the first character that cannot be part of a name — $X/bar expands X, not X/bar.

    $ declare X=world
$ echo "hello $X"
hello world
$ echo 'hello $X'
hello $X
  6. 75

    Expansion with braces br2Medium

    ${X} delimits the name explicitly, so ${X}abc works where $Xabc would look up the wrong name.

  7. 76

    Expanding empty variables my0Easy

    An unset variable expands to the empty string silently — no error, no literal $X left behind. map.get(name).cloned().unwrap_or_default() is the whole stage.
